Bulk send recovery

Send bulk email from Google Sheets past the Gmail daily limit

You hit a daily sending cap mid-batch: some rows went out, some did not. The fix is not a tool that promises to exceed the limit — no add-on can. The fix is splitting the batch across days so already-sent rows can never be emailed twice.

Quick answer

Copy the sheet. Resolve the exact pending payload for every row. Already-SENT rows stay blocked by the 30-day protected-message fingerprint. Approve the unchanged preview once, then send only the remaining rows the next day.

First-run path

  1. Copy the spreadsheet; never resume a half-sent batch on the live Sheet.
  2. Replace real recipient addresses with test inboxes you control.
  3. Map one recipient column and one subject/body template.
  4. Run Preflight and Preview pending: confirm which rows are SENT, unsent, or SEND_UNCERTAIN.
  5. Review every exact recipient, subject, body, CC, and BCC for the unsent rows.
  6. Approve the unchanged preview once, then send only the remaining rows.
  7. Confirm each row becomes SENT before the next day's batch.

Boundary

Gmail enforces daily sending limits at the account level. No add-on, script, or workaround sends more than your account allows in a day. Anyone promising otherwise is selling something Google will block. The safe strategy is planned multi-day batches with duplicate protection — not limit evasion.

When this works best

After a cap-hit

You know exactly which rows sent and which did not, because every row carries a SENT / SEND_UNCERTAIN status instead of a vague "done".

Before the next send

A 30-day ledger blocks replays even if rows move, get copied, or have their status cells cleared — the classic cause of accidental double sends.

FAQ

Will this let me exceed the daily limit?

No. It lets you finish a large send across multiple days without emailing anyone twice. The limit still applies per day.

What if a row shows SEND_UNCERTAIN?

Do not retry it blindly. Check the recipient inbox first, then mark it verified sent or reset it. Ambiguous sends stay blocked until a human decides.
