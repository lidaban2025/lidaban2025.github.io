FormSuite safe migration protocol

Move one workflow without trusting a silent write.

A FormSuite migration test starts with a copied Google Form or Sheet. It should reveal unsupported structure, show the exact change or output, require an explicit action, and end in a result an operator can independently verify.

Choose a migration test

The six-step contract

  1. Copy: duplicate the Form, Sheet, and one template before testing.
  2. Inspect: check permissions, source structure, mappings, duplicates, and unsupported features.
  3. Preview: show the exact choices, email payload, or row values before execution.
  4. Approve: invalidate approval when the underlying data or configuration changes.
  5. Execute once: update one question, send one controlled batch, or generate one file.
  6. Verify: inspect the respondent preview, row status, recipient inbox, or generated output.

Not supported by this promise

Safe migration does not mean complete feature parity, exactly-once email delivery, respondent-time dependent dropdowns, live inventory locking, booking, payment, legal approval, or enterprise document management. When a workflow needs those guarantees, FormSuite should reject the fit instead of forcing an add-on migration.
