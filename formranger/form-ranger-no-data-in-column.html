Quick diagnosis

Wrong file or lost access

Select the spreadsheet again with the same Google account that owns or can open it.

Renamed tab or header

A saved mapping can point to a name that no longer exists after a Sheet edit.

Blank values

Keep one header in row 1 and at least one real value beneath it. Whitespace-only cells do not count.

Editor/public mismatch

The final check is the respondent-facing preview, not only the mapping screen or Form editor.

Safe recovery sequence

  1. Make a copy of the affected Google Form.
  2. Leave the original source spreadsheet unchanged while diagnosing.
  3. In the copied form, select the source file and confirm the exact tab and header.
  4. Reduce the test column to two values such as Alpha and Beta.
  5. Link one supported question and run Preflight.
  6. Only if Preflight passes, run Update now and open the public preview.
  7. Move the remaining mappings only after the copied-form result is correct.

What the newer workflow changes

FormSuite Choice Sync separates source access, tab lookup, column lookup, empty-source detection, choice preview, update result, and public-preview confirmation. A failed check reports the recovery stage instead of treating a saved mapping as proof that the form changed.

It also refuses to write when the target question contains section routing, a quiz answer key, or more than 1,000 incoming choices.

Not a fit

This workflow does not provide respondent-time dependent dropdowns, booking, inventory locking, payments, or live filtering. It refreshes owner-controlled choice lists before respondents use the form.
