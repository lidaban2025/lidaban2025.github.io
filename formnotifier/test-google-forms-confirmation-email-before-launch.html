How to test a Google Forms confirmation email before launch

A practical checklist for testing Google Forms confirmation emails before launch, including respondent email source, template variables, test send, and delivery report checks.

One copied form

Prepare a registration test

  1. Copy a form you own. Use only synthetic data; remove student, customer and payment information.
  2. Add a short-answer question titled Name and another titled Email. For this test, use a Google account and inbox you control.
  3. Install FormNotifier, open the copied form and launch its sidebar. Enable owner alerts and respondent confirmations. Select Email as the respondent address field if the form does not collect email automatically.

Download checklist and email templates

Two distinct messages

Save these starter templates

Operator subject: Test registration: {{Name}}

Operator body: A synthetic registration was received from {{Name}}. Please review the copied form.

Respondent subject: We received your registration

Respondent body: Hi {{Name}}, we received your registration. This message confirms receipt only; it does not reserve a place or confirm approval.

Save the settings before testing. Merge fields must match the question titles exactly. Leave every additional recipient empty unless you control that inbox too.

Verify the actual submission

Do not stop at “Saved” or “Test sent”

  1. Run Preflight and resolve any address, permission or quota issue.
  2. A sidebar test is a preliminary check. Some installed versions test only the operator path; it does not establish that a real respondent will receive a confirmation.
  3. Temporarily publish only the copied synthetic form if Google requires publication for a test submission. Submit one response: Name = Alpha; Email = an inbox you control.
  4. Open the operator inbox and confirm the alert contains Alpha. Open the respondent inbox and confirm the separate receipt message arrived, with no unresolved {{Name}} marker.
  5. Check spam and the notification report. A saved configuration, a successful send call or a report alone does not prove inbox delivery.
  6. Disable notifications and unpublish the copied form after testing. Keep your live form unchanged until both messages have been checked.
Stage-only support

If either email is missing

Report the last completed stage: install, Preflight, settings saved, synthetic submission, operator inbox, or respondent inbox. Include only sanitized error text. Do not send screenshots, Form/Sheet URLs or IDs, email addresses, response content, passwords or license keys.

First-run feedback: What did you expect? At which stage did you think the workflow was complete? Which result would make you trust it next time?
