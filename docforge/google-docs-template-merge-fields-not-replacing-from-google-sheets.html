1. Tag match

Compare every merge tag with its Sheet header

Spaces, punctuation, capitalization, and hidden trailing characters can make a tag look correct while it points to no column. Copy the header text directly into the template tag for the one-row test.

2. Row data

Inspect the exact source row

Confirm the test row is not filtered out, the required cells are not blank, and formulas have finished calculating. Do not infer the result from a different row.

3. Files

Verify the selected template and access

Open the exact Google Docs template and output folder from the same account running the merge. A moved, deleted, or inaccessible file can look like a placeholder problem.

4. Scope

Duplicate the Sheet and template

Keep the live job unchanged. A copied-Sheet test removes the risk of duplicate production files while you isolate the failing mapping.

After the first file works, protect the repeat run

Stable row ID

Choose a unique non-blank key

Use an order, invoice, certificate, member, or case ID when available. Duplicate or blank keys should block Preflight instead of weakening duplicate protection.

Durable proof

Require a new proof after workflow changes

A changed template version, header set, mapping, stable key, naming pattern, folder, or output must invalidate the previous proof.

Manifest

Reuse unchanged successful outputs

Do not generate an accessible unchanged output twice. Show missing, changed, and failed states instead of silently hiding them.

Retry failed only

Leave successful rows untouched

Retry only failed rows, then compare expected, generated, reused, changed, and failed totals.

One-row recovery sequence

  1. Copy the Google Sheet and duplicate the Google Docs template.
  2. Keep one synthetic source row with obvious values such as Alpha, Project A, and 100.
  3. Map every required template tag and run Preflight.
  4. Preview that exact row and confirm the output name and mapped values.
  5. Generate one file, open it, and compare every expected field.
  6. Only then move the corrected mapping back to the production workflow.

What counts as fixed?

A sidebar message alone is not proof. The file must open with the copied-row values, the saved proof must still match the workflow, and the reconciliation must explain generated, reused, changed, and failed rows. Internal QA is product evidence, not a customer success signal.

FAQ

Why is Autocrat not replacing merge fields?

Check exact tag-to-header matching, the selected Sheet tab, blank source cells, template access, and the specific row being merged. Test one copied row before changing the live job.

Should I rerun the whole batch?

No. Generate and open one file first. A full rerun can create duplicates without proving the mapping is fixed.

Is DocForge an official Autocrat replacement?

No. DocForge is independent and is positioned for a narrow single-template, one-row proof—not universal feature parity.

What should happen when only some rows failed?

Keep successful outputs unchanged, repair the failing source or mapping, retry failed rows only, and review the reconciliation totals before another production run.
